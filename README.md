 최소 비용 신장 트리(MST) 알고리즘 비교 및 분석

1. 실험 개요 및 환경

본 과제는 정점이 50개인 가중치 무방향 단순 연결 그래프에 대하여 그래프의 밀도(희소 그래프, 밀집 그래프), 그래프 표현 방법(인접 리스트, 인접 행렬), 그리고 MST 알고리즘(Kruskal, Prim)에 따른 메모리 사용량과 실행시간을 측정하고 비교 분석한 결과입니다.

정점의 개수: 50개 (0번 ~ 49번)

희소 그래프(Sparse Graph): 정점 50개, 간선 100개 (Case 1, Case 3 동일 그래프 사용)

밀집 그래프(Dense Graph): 정점 50개, 간선 600개 (Case 2, Case 4 동일 그래프 사용)

가중치 범위: 1 ~ 100 사이의 양의 정수

측정 환경: 64비트 운영체제 및 C 컴파일러 기준 (int 4바이트, 간선 구조체 12바이트, 리스트 노드 16바이트)

2. 실험 측정 결과 (4가지 경우)

Vertices      : 50

Case 4 : Dense Graph - Adjacency Matrix - Prim
Vertices      : 50

3. 각 경우의 MST 전체 비용과 간선 수 분석

[1] MST 간선 수 확인

정점이 50개인 연결 그래프에서 사이클 없이 모든 정점을 연결하는 신장 트리의 간선 수는 항상 '정점 수 - 1'개입니다.

그래프 생성 단계에서 깊이 우선 탐색(DFS)을 통해 모든 정점이 연결된 연결 그래프임을 확인하였으므로, 4가지 경우 모두 MST에 포함된 간선의 수는 49개로 동일합니다.

[2] MST 전체 비용(Total Weight) 비교

희소 그래프를 사용한 Case 1(Kruskal)과 Case 3(Prim)은 동일한 정점과 간선, 가중치를 가진 그래프를 대상으로 수행되었기 때문에 MST의 전체 비용이 1142로 정확히 일치합니다.

밀집 그래프를 사용한 Case 2(Kruskal)와 Case 4(Prim) 역시 동일한 그래프를 사용하였으므로 MST의 전체 비용이 285로 정확히 일치합니다.

동일한 가중치를 가진 간선이 여러 개 존재할 경우 두 알고리즘이 선택하는 개별 간선의 구성은 일부 다를 수 있으나, 최종적으로 구해지는 MST의 전체 비용은 항상 같습니다.

또한 밀집 그래프(간선 600개)는 희소 그래프(간선 100개)보다 선택할 수 있는 작은 가중치의 간선 후보가 훨씬 많기 때문에 전체 MST 비용이 더 작게 측정됩니다.

4. 인접 리스트와 인접 행렬의 메모리 사용량 비교

[1] 인접 리스트 + Kruskal 알고리즘의 메모리 구조 (Case 1, Case 2)

인접 리스트 방식은 실제 존재하는 간선만큼만 동적으로 노드를 할당하므로 정점 수와 간선 수에 비례하여 메모리를 사용합니다.

그래프 헤더 구조체(408 Bytes) + 양방향 연결 리스트 노드(간선 수의 2배 x 16 Bytes) + 정렬용 간선 배열(간선 수 x 12 Bytes) + Union-Find 부모 배열(200 Bytes) + MST 결과 배열(588 Bytes)로 구성됩니다.

Case 1(간선 100개)에서는 노드가 200개 생성되어 총 5,596 Bytes의 적은 메모리만 사용합니다.

반면 Case 2(간선 600개)에서는 노드가 1,200개로 늘어나고 간선 배열 크기도 커져서 메모리 사용량이 27,596 Bytes로 약 5배 가까이 급증합니다.

[2] 인접 행렬 + Prim 알고리즘의 메모리 구조 (Case 3, Case 4)

인접 행렬 방식은 간선의 개수와 상관없이 가로 50칸, 세로 50칸(총 2,500칸)의 2차원 배열 공간을 고정적으로 사용합니다.

인접 행렬 구조체(10,008 Bytes) + Prim 보조 배열 3개(visited, minWeight, parent 총 600 Bytes) + MST 결과 배열(588 Bytes)로 구성됩니다.

따라서 간선이 100개인 Case 3과 간선이 600개인 Case 4 모두 메모리 사용량이 11,196 Bytes로 완전히 동일합니다.

[3] 메모리 사용 차이 요약

희소 그래프에서는 필요한 간선만 저장하는 인접 리스트(5,596 Bytes)가 인접 행렬(11,196 Bytes)보다 메모리를 절반 수준으로 절약합니다.

그러나 밀집 그래프에서는 인접 리스트의 각 노드가 다음 노드의 주소를 저장하는 포인터 변수를 추가로 가지고 있어(포인터 오버헤드), 간선이 많아질수록 오히려 인접 행렬(11,196 Bytes)보다 인접 리스트(27,596 Bytes)가 2배 이상의 메모리를 소모하게 됩니다.

5. Kruskal 알고리즘과 Prim 알고리즘의 실행 특성 및 실행시간 차이

[1] Kruskal 알고리즘의 실행 특성 (간선 중심 알고리즘)

그래프의 모든 간선을 배열로 추출한 뒤 가중치 오름차순으로 정렬하고, 가장 가중치가 작은 간선부터 차례대로 Union-Find 자료구조를 이용해 사이클 발생 여부를 검사하며 49개의 간선을 선택합니다.

전체 실행시간 중 가장 큰 비중을 차지하는 과정은 '간선 정렬' 단계입니다.

따라서 간선 수가 100개(Case 1)에서 600개(Case 2)로 6배 증가하면, 정렬 과정에서 비교하고 교환해야 하는 연산 횟수가 크게 증가하여 실행시간이 0.0180 ms에서 0.3420 ms로 뚜렷하게 늘어납니다.

[2] Prim 알고리즘의 실행 특성 (정점 중심 알고리즘)

시작 정점(0번)에서 출발하여 현재 MST에 포함된 정점 집합과 인접한 정점들 중 최소 비용(minWeight)을 가진 정점을 하나씩 선택하여 MST를 확장합니다.

인접 행렬을 사용할 경우, 정점 50개를 모두 선택할 때까지 매 단계마다 50개의 정점을 확인하여 최소 비용 정점을 찾고 인접 행렬의 해당 행(50칸)을 스캔하며 비용을 갱신합니다.

즉, 간선의 개수가 100개이든 600개이든 항상 정점 수(50개)의 제곱에 비례하는 일정한 횟수만큼만 반복문을 수행하므로, Case 3(0.0150 ms)과 Case 4(0.0160 ms)의 실행시간은 거의 차이가 없습니다.

6. 종합 결론: 그래프의 밀도가 각 방법의 성능에 미치는 영향

희소 그래프(간선이 적은 경우)에서는 빈 공간을 저장하지 않는 인접 리스트가 메모리 측면에서 훨씬 효율적이며, 정렬해야 할 간선의 수가 적기 때문에 Kruskal 알고리즘이 빠르고 효율적으로 동작합니다.

밀집 그래프(간선이 많은 경우)에서는 인접 리스트의 노드 포인터 오버헤드와 Kruskal 알고리즘의 간선 정렬 비용이 급격히 증가하여 메모리 사용량과 실행시간이 모두 크게 늘어납니다.

반면 인접 행렬 기반의 Prim 알고리즘은 그래프의 간선 밀도가 높아져도 메모리 사용량(11,196 Bytes)과 실행시간이 일정하게 유지됩니다.

결론적으로 간선이 적은 희소 그래프에서는 '인접 리스트 + Kruskal 알고리즘'을 사용하는 것이 유리하고, 간선이 많은 밀집 그래프에서는 '인접 행렬 + Prim 알고리즘'을 사용하는 것이 메모리와 실행시간 모두에서 훨씬 뛰어납니다.
